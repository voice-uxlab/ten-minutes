# 로그인 문의 ID

로그인 화면의 **문의 정보 복사** 버튼은 표시된 ID만 복사한다. ID는 오류 유형을 나타내는 `LGN-번호`로 시작한다. 서버 요청 ID가 있으면 `/req_…`가 붙는다. 예를 들어 `LGN-003/req_7f42d2b5f0e34cf8a7e47419b14f1980`에서 `LGN-003`은 아래 표로 확인하고, `req_…`는 FastAPI 또는 Vercel 로그에서 `request_id`로 검색한다. ID에는 세션 값이나 사용자 개인정보를 포함하지 않는다.

| 문의 코드 | 기존 경고 또는 판정 | 내부 확인 항목 |
| --- | --- | --- |
| `LGN-001` | `OAUTH_AUTHORIZE_FAILED` | 카카오 인증 시작 요청을 처리하지 못했다. 요청 ID로 인증 시작 로그를 확인한다. |
| `LGN-002` | `OAUTH_FAILED` | 브라우저가 취소와 인증 시작 실패 이외의 인증 실패 상태를 받았다. 리다이렉트 경로와 인증 로그를 확인한다. |
| `LGN-003` | `SESSION_COOKIE_MISSING` · 로그인 상태 조회 401 | `/api/v1/users/me` 요청에 서비스 세션 쿠키가 없다. 콜백 응답과 프론트·API 도메인, 프록시, 쿠키 설정을 확인한다. |
| `LGN-004` | `SESSION_COOKIE_REJECTED` · 로그인 상태 조회 401 | 쿠키가 도착했으나 해당 세션 또는 사용자를 확인하지 못했다. 서버에서 세션의 존재 여부, 만료·폐기 여부를 확인한다. |
| `LGN-005` | `SESSION_COOKIE_UNKNOWN` · 로그인 상태 조회 401 | 프론트가 쿠키 실패를 분류할 수 있는 지원 코드를 받지 못했다. 응답을 만든 API 및 프록시를 확인한다. |
| `LGN-006` | 로그인 상태 조회의 401 이외 HTTP 오류 | 요청 ID로 `/api/v1/users/me`의 HTTP 상태와 서버 로그를 확인한다. |
| `LGN-007` | `AUTH_LOOKUP_UNAVAILABLE` | 로그인 상태 조회 응답을 받지 못했거나 8초 안에 확인하지 못했다. 네트워크와 해당 시간대의 서비스 상태를 확인한다. |
| `LGN-008` | `OAUTH_RETURN_UNCONFIRMED` | 신규 로그인 시도 후 돌아왔지만 결과를 분류할 응답을 확인하지 못했다. 카카오 인증에서 돌아온 방법과 재현 시각을 확인한다. |
| `LGN-009` | 로그인 취소 | 카카오 인증 흐름에 취소가 전달됐다. 다시 로그인을 시작할 수 있다. |

이전 화면의 “콜백 응답에서 세션 쿠키 발급 확인”과 “콜백의 세션 쿠키 발급 여부 미확인”은 로그인 결과를 판단할 때 쓰던 보조 표시였다. 문의 유형은 위 표의 상태 조회 결과로 판정한다. 코드에 `req_…`가 없으면 발생 유형만 알 수 있으므로, 개별 요청을 확인해야 할 때는 재현 시각과 브라우저를 함께 확인한다.
