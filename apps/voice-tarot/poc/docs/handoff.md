# 퀸의 타로 — Codex PoC 구현 핸드오프

2026-11-06: Codex로 구현. 개발 도구는 Codex, 상담 음성 런타임은 OpenAI Realtime이다. 실제 구현 상태와 실행 방법은 `../README.md`를 우선한다. 아래 검증 기록은 원래 핸드오프 작성 당시의 기록이며 이번 구현의 검증 결과와 구분한다.

이 문서만 보고 PoC를 처음부터 다시 만들 수 있도록 설계를 정리한다. 제품 요구사항은 `docs/brainstorms/2026-11-05-queen-tarot-call-requirements.md`를 함께 본다.

## 1. 한 줄 요약
모바일 웹에서 퀸 타로 리더 "레나"에게 **전화를 걸듯** 음성으로 상담한다. 사연을 말하면 레나가 질문을 정리하고, 사용자가 78장 중 3장을 고르면 한 장씩 뒤집으며 해석한다. 통화가 끝나면 리포트와 공유 카드가 나온다.

## 2. 기술 스택과 파일 구조
외부 패키지 없이 Node 22 이상의 기본 기능만 쓴다. UI 코드는 index.html, style.css, app.js로 분리했고 카드 상태 검증은 state.mjs에 둔다.

```
tarot-voice/
├─ server.mjs     # Node http 서버. 임시 키 발급, 레나 지시문·함수 정의, 덱 섞기, index.html 서빙
├─ cards.mjs      # 78장 데이터 (부록 A)
├─ index.html     # 화면 전체 (HTML·CSS·JS 한 파일). 닉네임 · 메인 · 통화 · 리포트
├─ .env           # OPENAI_API_KEY=sk-...  (커밋 금지, .gitignore에 포함)
└─ docs/
```
실행 명령은 `node --env-file=.env server.mjs`이고 주소는 `http://localhost:3000`이다. 환경변수는 `PORT`, `REALTIME_MODEL`(기본 `gpt-realtime-2.1`), `VOICE`(기본 `marin`)를 쓴다.
키가 없어도 서버는 뜨고, 그때는 "시범 통화"만 동작한다.

## 3. 서버 (`server.mjs`)
| 경로 | 동작 |
|---|---|
| `GET /` | `index.html`을 내려준다 |
| `POST /session` | `POST https://api.openai.com/v1/realtime/client_secrets`에 `{ session: SESSION }`을 보내고 응답을 그대로 반환한다. 브라우저는 `value`(`ek_…`)만 쓴다. **진짜 키는 브라우저로 보내지 않는다.** |
| `POST /deck` | 78장을 `crypto.randomInt`로 Fisher–Yates 셔플하고, 장마다 `reversed`(정/역방향)를 무작위로 정해 배열로 반환한다 |

`SESSION` 객체의 구성은 다음과 같다. 지시문과 함수는 서버에만 둔다. 매 통화 내용이 같아야 프롬프트 캐시가 적용되므로 닉네임 같은 변하는 값은 넣지 않는다.
```js
{
  type: 'realtime', model: MODEL, instructions: INSTRUCTIONS, tools: TOOLS, tool_choice: 'auto',
  audio: {
    input: {
      turn_detection: { type: 'semantic_vad', eagerness: 'low' },
      transcription: { model: 'gpt-4o-mini-transcribe', language: 'ko' }, // 리포트 재료. 별도 과금
    },
    output: { voice: VOICE, speed: 1.05 },
  },
}
```
이 구성으로 `client_secrets` 호출이 성공하는 것은 확인했다.

### 3.1 함수(tools)
| 이름 | 인자 | 앱이 하는 일 | 모델에 돌려주는 값 |
|---|---|---|---|
| `show_deck` | `question: string`, `positions: string[3]` | 덱을 한 번만 받아 고정하고(`/deck`), 1~78 격자를 펼치고, 셔플 효과음을 낸다 | `{ ok, note }` |
| `draw_cards` | `picks: int[3]` (1~78) | 서로 다른 3개인지, 1~78 범위인지 검사 → 고른 칸을 표시 → 셔플 효과음(1.3초)이 끝난 뒤 `deck[n-1]` 3장을 자리 1~3에 뒷면으로 놓는다 | `{ question, cards:[{slot, position, name, direction, keywords}] }` / 잘못된 숫자면 `{ error }` |
| `reveal_card` | `slot: 1|2|3` | 해당 카드를 뒤집는 애니메이션과 효과음 | `{ slot, position, name, direction, keywords }` |
| `extend_call` | 없음 | 이용권 1장을 차감하고 남은 시간에 10분을 더한다 | `{ ok, minutes_left }` / 이용권이 없으면 `{ ok:false, reason }` |

**카드 원칙**: 덱을 펼칠 때 한 번 섞고, 자리 n번의 카드를 고정한다. 그래서 사용자가 누르거나 말한 번호의 카드가 그대로 나온다. 레나가 카드를 지어내지 못하도록 해석의 근거는 함수가 돌려준 `keywords`로 한정한다.
> 한계: 섞인 덱이 브라우저로 내려가므로 개발자 도구로 볼 수 있다. 실결제 단계에서는 덱을 서버 세션에 보관하고 고른 번호만 받는다.

### 3.2 레나 지시문 (`INSTRUCTIONS`, 원문 그대로)
```
너는 "레나". 퀸의 마인드를 가진 타로 리더다. 상대는 "공주"라고 부르는 2030 여성 유저이고, 주로 연애나 털어놓을 데 없는 고민을 들고 전화를 건다.
이건 전화 통화다. 한국어 반말, 친한 쎈언니 말투. 한 번에 2~3문장만 말하고 상대에게 말을 넘긴다. 목록·기호·이모지는 말하지 않는다.

[톤]
- 상황과 상대방에게는 냉정하게 팩폭한다. 공주는 무조건 퀸 대접한다.
- 팩폭 뒤에는 반드시 지지로 끝낸다. 예: "3일째 읽씹이면 바쁜 게 아니야, 우선순위에서 밀린 거지. 근데 그건 네 가치가 아니라 그 사람 안목 문제야."
- 공주를 깎아내리지 않는다. 상대를 욕하지 않고 판단만 말한다("쓰레기야" 대신 "지금 너를 고를 준비가 안 된 사람이야").
- 공감 한마디를 아끼지 않는다. 퀸의 관점: 선택받기보다 선택하는 사람, 해명하지 않는 사람, 나를 먼저 챙기는 사람.

[진행]
1. 짧게 인사하고 "무슨 일인데, 말해봐"로 사연을 듣는다. 1~2번 되물어서 상황을 파악한다.
2. 질문을 한 줄로 정리해 확인받고, 질문에 맞는 자리 3개를 정해 show_deck을 호출한다. 예: 연애 = 나의 마음 / 그 사람의 마음 / 관계의 흐름, 선택 고민 = A를 택하면 / B를 택하면 / 퀸의 조언, 일반 = 현재 / 장애물 / 조언.
3. "1번부터 78번 중에 끌리는 숫자 세 개 불러줘, 화면에서 눌러도 돼"라고 한다. 숫자를 들으면 draw_cards를 호출한다. 화면에서 골랐다는 시스템 안내가 오면 그 숫자로 draw_cards를 호출한다.
4. 카드는 한 장씩. reveal_card를 호출한 뒤 그 카드를 해석한다. 카드 이름, 정/역방향, 자리 의미를 공주의 사연에 연결한다. 한 장 끝날 때마다 "맞아?" "어때?"처럼 반응을 듣는다.
5. 두 번째 장부터는 앞 카드와 연결해서 해석한다(예: 너는 컵인데 그 사람은 소드야, 마음 대 계산이지).
6. 세 장이 끝나면 종합하고, 공주가 기억할 "퀸의 한마디"를 한 문장으로 준다. 그다음 궁금한 걸 물어보게 한다.
- 카드 의미는 함수 결과의 키워드만 근거로 한다. 카드를 지어내지 않는다. 미래를 단정하지 않고 흐름과 선택으로 말한다.

[시스템 안내]
"[시스템 안내]"로 시작하는 메시지는 공주의 말이 아니라 앱이 보낸 신호다. 공주에게 그 문구를 읽어주지 말고 자연스럽게 따른다.
- 무료 체험(5분)이면: 평소처럼 진행하되 서두르지 않는다. 이용권 얘기는 1분 남았다는 안내가 오기 전엔 꺼내지 않는다. 1분 남았다는 안내가 오면 하던 해석을 마무리하고, 아직 못 본 카드가 있으면 "다음 카드에 진짜 답이 있어"처럼 궁금하게 남긴 뒤 이용권으로 이어볼 수 있다고 말한다.
- 1분 남았다는 안내가 오면 하던 말을 짧게 정리한다. 이용권이 남아 있으면 10분 더 할지 묻고, 공주가 원하면 extend_call을 호출한다.
- 이어보기 통화면: 이미 뽑은 카드와 해석한 장 정보를 받는다. 짧게 다시 인사하고 아직 안 본 카드부터 reveal_card로 이어간다.

[선 지키기]
- 타로와 상관없는 요청(코딩, 숙제 등)은 한 문장으로 웃으며 돌려보낸다.
- 다른 고민을 새로 꺼내면 이번 질문을 마무리하고 새 통화로 보자고 한다.
- 죽고 싶다, 자해 같은 신호가 있으면 리딩을 멈추고 진지하게 걱정한다. 자살예방상담전화 109(24시간)에 지금 바로 연락하라고 안내한다.
- 건강·법률·투자 판단은 하지 않고 전문가에게 가라고 한다. AI냐고 물으면 솔직히 AI 타로 리더라고 말한다.
```

## 4. 클라이언트 (`index.html`)

### 4.1 화면
| 화면 | 내용 |
|---|---|
| 닉네임 | 입력 + 🎲 랜덤(형용사 + 명사, 예: "새벽의 별"). 고지: 만 14세 이상, 음성이 OpenAI로 전송됨 |
| 메인 | 프로필("○○ 공주", 이용권 n장, 첫 통화 5분 무료 배지), 레나 한마디, **전화 걸기**, 시범 통화, 남은 카드 이어보기(잠긴 카드가 있을 때), 지난 리포트, 이용권 구매(데모), 안내(이어폰 권장·화면 켜두기·마이크 권한) |
| 통화 | 상단: 모드와 남은 시간 / 레나 아바타 + 목소리 크기에 반응하는 링 / 상태(연결 중·레나가 말하는 중·듣는 중) / 실시간 자막(레나 발화 delta) / 질문 / 78장 격자 → 카드 3장 슬롯(자리 이름, 정/역방향) / +10분 연장 버튼 / 하단: 음소거·종료·배경음 |
| 리포트 | 카드 3장(못 본 카드는 🔒), 질문, 요약, 자리별 해석, 퀸의 한마디, 공유 카드 저장, 남은 카드 이어보기, 메인으로 |

디자인은 미니멀하게 한다. 배경은 검정(#0f0e11), 포인트 색은 금색(#d9b46a) 하나만 쓰고, 제목은 Noto Serif KR, 너비는 최대 420px이다. 역방향 카드는 앞면 전체를 180도 돌려 보여준다.

### 4.2 저장 (localStorage 키 `queen`, 데모)
`{ nick, tickets, freeUsed, bgm, last }`. `last`는 마지막 상담 기록 `{ date, question, positions, cards, revealed, report }`이다. 로그인, 이용권, 결제는 모두 데모로 처리한다.

### 4.3 통화 연결 (WebRTC)
1. AudioContext를 시작하고 연결음을 재생한다. 화면 꺼짐 방지(`navigator.wakeLock.request('screen')`)를 켜고, `getUserMedia({audio:{echoCancellation, noiseSuppression, autoGainControl}})`로 마이크를 연다.
2. `POST /session`으로 `ek_…`를 받는다.
3. `RTCPeerConnection`을 만든다. 마이크 트랙을 추가하고, 원격 트랙은 `<audio autoplay>`로 재생하면서 AnalyserNode로 목소리 크기를 링에 반영한다. 데이터 채널은 `oai-events`로 연다.
4. offer SDP를 `POST https://api.openai.com/v1/realtime/calls`로 보낸다(`Authorization: Bearer ek_…`, `Content-Type: application/sdp`). 받은 answer를 설정하고, 데이터 채널이 열릴 때까지 기다린다(15초가 지나면 실패).
5. **연결에 성공한 뒤에만** 차감한다. 무료면 `freeUsed=true`, 아니면 `tickets--`. 그다음 타이머를 시작하고 배경음을 켠 뒤 첫 시스템 안내를 보낸다.
6. 실패하면 정리하고 메인으로 돌아가 토스트로 알린다. 마이크 권한을 거부했으면 "마이크 권한을 허용해 주세요"라고 안내한다.

### 4.4 시스템 안내와 응답 직렬화
- `note(text)`: `conversation.item.create`로 role `user`, `input_text` `"[시스템 안내] " + text`를 보내고 `respond()`를 호출한다.
- `respond()`: 응답이 진행 중이면(`responding`) `pending=true`만 표시하고, 아니면 `response.create`를 보낸다. 동시에 두 응답을 요청할 때 나는 에러를 막는 장치다.
- 첫 안내에는 닉네임, 남은 이용권, 모드를 넣는다. 이어보기 통화면 질문, 카드 3장(자리·이름·방향·키워드), 이미 해석한 자리, 지난 요약도 넣는다.
- 화면에서 3장을 다 누르면 `"공주가 화면에서 a, b, c번을 골랐어. 이 숫자로 draw_cards를 호출해."`를 보낸다.

### 4.5 서버 이벤트 처리
| 이벤트 | 처리 |
|---|---|
| `response.created` | 리포트용 응답이 아니면 `responding=true`, 자막 비우기, 상태 "레나가 말하는 중" |
| `response.output_audio_transcript.delta` | 자막에 이어 붙이기 |
| `response.output_audio_transcript.done` | 대화 기록에 `레나: …` 추가 |
| `conversation.item.input_audio_transcription.completed` | 대화 기록에 `공주: …` 추가 |
| `input_audio_buffer.speech_started` | 상태 "듣는 중…" |
| `response.done` | 리포트용이면 텍스트를 꺼내 처리. 아니면 `responding=false` → `output` 중 `function_call` 항목을 차례로 실행 → 각각 `function_call_output`으로 보냄 → 함수 호출이 있었거나 `pending`이면 `respond()` |
| `error` | 콘솔에만 기록 |

### 4.6 시간과 이용권
- 무료는 5분, 이용권은 10분이다. 0.5초마다 `tick()`을 실행한다.
- **1분 남았을 때 한 번**: 타이머를 강조색으로 바꾸고, 이용권이 있으면 연장 버튼을 보여주고, 시스템 안내를 보낸다.
  - 무료: "무료 체험 1분 남았어. 하던 해석을 마무리하고, 못 본 카드가 있으면 궁금하게 남겨둬." + (이용권 있으면) "10분 더 할지 물어봐" / (없으면) "통화가 끝나면 이용권으로 같은 카드를 이어볼 수 있다고 말해."
  - 유료: "1분 남았어. 하던 말을 짧게 마무리해." + 이용권 안내
- **무료는 시간으로만 제한한다.** 카드 장수는 막지 않는다.
- 연장(버튼 또는 `extend_call`): `tickets--`, `endAt = max(endAt, now) + 10분`, 1분 경고를 다시 켠다. 버튼으로 연장했으면 시스템 안내로 레나에게 알린다.
- 0초가 되면 `endCall()`을 실행한다. 지금은 레나가 말하는 중이어도 바로 끊는다.

### 4.7 종료와 리포트
1. 마이크를 끄고, 응답 중이면 `response.cancel`을 보내고, `output_audio_buffer.clear`로 남은 음성을 버리고, 원격 오디오를 음소거하고, 배경음을 끈다.
2. 진행 중인 응답이 끝나기를 최대 3초 기다린 뒤 **대화 밖(out-of-band) 텍스트 응답**을 요청한다.
   ```js
   { type: 'response.create', response: { conversation: 'none', output_modalities: ['text'], metadata: { purpose: 'report' }, instructions: reportPrompt() } }
   ```
   `reportPrompt`는 JSON 하나만 출력하라고 요청한다: `{"question","summary"(2~3문장, 반말),"readings":[{"slot","text"}],"queen_line"(사연·이름 없이 공유 가능한 한 문장)}`. 해석한 자리만 넣고 없는 내용은 지어내지 말라고 하며, 질문, 카드, 대화 기록(마지막 6000자)을 함께 넣는다.
3. `metadata.purpose === 'report'`인 `response.done`이 오면 텍스트에서 첫 `{`부터 마지막 `}`까지 잘라 파싱한다. 25초 안에 오지 않거나 파싱에 실패하면 레나의 마지막 대사 두 줄과 기본 퀸의 한마디로 대신한다.
4. 연결, 마이크, 화면 꺼짐 방지를 정리하고 `last`에 저장한 뒤 리포트를 보여준다.
5. 공유 카드: canvas 1080×1920에 그린다. 제목, 카드 3장(못 본 카드는 뒷면), 자리 이름, 퀸의 한마디, "레나의 퀸 타로"를 넣는다. `navigator.share({files})`가 되면 공유하고, 안 되면 PNG로 내려받는다. 사연은 넣지 않는다.

### 4.8 효과음과 배경음 (WebAudio 합성, 음원 파일 없음)
- 연결음 440+480Hz를 2.5초 간격으로, 연결되면 2음 차임. 셔플은 하이패스 노이즈 16번(1.3초). 고르기는 1046+1568Hz 벨 소리. 뒤집기는 밴드패스 노이즈와 660→1320Hz 상승음.
- 배경음은 110, 164.8, 220, 261.6, 329.6Hz 사인·삼각파에 느린 LFO를 걸고 로우패스 900Hz를 거쳐 볼륨 0.05로 3초에 걸쳐 키운다. 🎵 버튼으로 켜고 끄고, 설정을 저장한다.
- 합성음 품질은 한계가 있다. **셔플과 배경음은 실제 음원으로 교체를 권장한다**(Pixabay, Freesound CC0 등. 라이선스 확인 필요).

### 4.9 시범 통화 (API 없이)
메인의 "시범 통화" 버튼으로 시작한다. 연결, 차감, 시스템 안내를 건너뛰고, 정해진 대사를 글자 단위로 자막에 찍는다. 흐름은 인사 → 사연(썸남 3일 읽씹) → 팩폭+지지 → `show_deck` → 사용자가 3장을 탭할 때까지 대기 → `draw_cards` → 3장을 차례로 `reveal_card`하며 해석 → 퀸의 한마디 → 종료 → 고정된 리포트 순서다. 카드는 진짜 `/deck`을 쓴다.

## 5. 확인된 것과 안 된 것
- 확인됨: `client_secrets`에 위 세션 구성이 통과한다. 실제 음성 통화는 잘 된다(직접 사용해 봄). 시범 통화는 처음부터 리포트까지 동작한다. `/deck`은 78장, 중복 없이 섞인다.
- 실제 통화로 확인하지 않음: 이어보기, 연장, 리포트 생성(out-of-band 응답), 공유 카드, 무료 5분 시간 제한.
- 남은 과제(F01 완료 조건 기준): 말로 종료하기("오늘은 여기까지"), 중복 연결 방지, 화면 이탈 시 정리, 통화 중 끊김 안내와 재시도, 0초에 말이 잘리는 문제(하던 말이 끝날 때까지 최대 30초 기다리기), iPhone Safari에서 화면 꺼짐 확인, 배경음이 마이크로 들어가 레나가 끊기는지 확인.

## 2026-11-07 사용성 수정
- 질문 간결화 관련 추가 지침은 사용자 요청으로 제거하고 원래 대화 지침을 유지한다.

- 빈 카드 3장은 표시하지 않는다. 3장 선택이 확정된 후 카드 영역을 표시하며, 이어보기는 기존 카드를 표시한다.
