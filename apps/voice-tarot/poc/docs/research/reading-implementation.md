# 질문별 리딩 구현 내역

작성일: 2026-11-14. 적용 범위: 로컬 Voice Tarot / 기존 레나 UI와 Typecast 음성.

## 적용한 동작

| 영역 | 구현 |
|---|---|
| 질문별 배치 | 한 가지 초점 1장, 두 방향 비교 2장, 상황·관계·변화 3장, 득실 비교 4장, 선택과 실행 5장 |
| 사용자 확인 | 질문·자리·장수·선택지 이름을 화면과 음성으로 확인. 수정 시 후보 번호를 초기화하고 다시 확인 |
| 카드 선택 | 터치와 음성 모두 서버 상태를 갱신. 부분 선택 누적, 중복·범위 밖·이미 사용한 번호 제외, 정확한 장수 확인 후 확정 |
| 리딩 | 자리별 해석 또는 카드 그룹 해석. 비교는 기회끼리, 부담끼리 함께 읽고 종합 |
| 해석 방식 | 레나 안에서 관계 탐색·선택 분석·변화 탐색 정책 선택. 별도 인물이나 마르세유·토트 전문가를 만들어낸 것은 아님 |
| 카드 지식 | 78장 모두 전통 RWS 참고 도상, 현대적 핵심 의미, 맥락적 역방향, 성찰 질문, 출처와 버전 |
| 추가 카드 | 종합 뒤 특정 자리의 보충 질문 제안 → 사용자 동의 → 남은 번호 중 한 장 선택. 상담당 최대 한 장 |
| 이어보기 | 서버 재시작 후에도 같은 덱·카드·배치·마스터 유지. 공개와 해석 진행을 따로 기록. 기존 3장 기록도 선택된 카드 그대로 복원 |
| 화면과 리포트 | 선택 전 카드 없음. 선택한 수만큼 표시. 5장 및 추가 카드 포함 최대 6장 배치·이미지 저장 지원 |
| 프롬프트 | 공감 유지. 근거 없는 속마음 단정, 역방향=불운, 결제 유도용 미완성 답변 제거 |

## 코드 구조

- `spreads.mjs`: 배치 정의, 자리 질문, 비교 그룹, 마스터 정책, 버전.
- `card-knowledge.mjs`: 출처를 포함한 78장 현대적 RWS 적용 데이터. 원전 직역·임상 근거로 표시하지 않음.
- `reading.mjs`: 확인·선택·공개·그룹 리딩·추가 카드의 상태 전이 및 모델에 전달할 맥락.
- `reading-store.mjs`: 비공개 서버 덱과 상태의 파일 저장. 상담별 불투명 ID, 원자적 저장, 동시 요청 순서 유지.
- `server.mjs`: `/reading` API와 기존 Realtime 세션 발급. 아직 뽑지 않은 덱은 모델과 브라우저에 반환하지 않음.
- `tools.mjs`, `instructions.mjs`: 실제 Realtime 함수 스키마와 상담 정책.
- `app.js`, `ui.mjs`, `index.html`, `style.css`: 가변 장수·정책 선택·추가 카드 동의·복원·리포트.

## 검증

- `npm test`: 35개 테스트 통과. 1~5장, 부분·중복 선택, 동시 터치, 질문 변경, 재추첨 방지, 출처 데이터, 그룹 해석, 추가 카드 동의, 저장과 재시작, 이전 기록 복원, 실제 HTTP 라우트, UI 및 기존 음성 스트리밍 포함.
- 브라우저: 데스크톱 1200px 및 모바일 390px에서 질문 수정 → 5장 배치 → 4장 선택 시 한 장 추가 요청 → 확정 → 공개 → 두 카드 비교 강조 → 리포트 확인. 가로 넘침 없음.
- 실제 OpenAI Realtime 연결: 세션 발급 200, 새 함수 11개 등록 확인. 이직 비교와 다음 행동을 요청한 입력에 `review_question`이 `decision` 및 실제 두 선택지 이름을 반환함.
- Typecast: 실행 중인 서버의 제공업체 `typecast`, 속도 `1.2` 유지 확인.
- 새 마이크 발화부터 Typecast 소리까지의 실제 음성 종단 테스트, 전문 타로 리더의 데이터 감수는 이번 검증에 포함하지 않음. 음성 선택 이벤트와 스트리밍은 자동 테스트로 확인.
- 전용 lint/typecheck 스크립트 없음. 변경한 JavaScript 구문 검사 및 Node 테스트 사용.

## 검토와 운영 범위

사용자의 솔로 작업 지시에 따라 별도 에이전트나 다른 모델에게 코드를 넘기지 않고 직접 검토했다. ce-simplify-code의 재사용·품질·효율성 기준으로 저장 스냅샷의 중복을 통합했다. ce-code-review의 독립 다중 에이전트 절차는 실행하지 않았으며, 독립 리뷰 완료로 주장하지 않는다. 로컬 수정에 대한 직접 검토에서는 선택지 이름 치환, 기록 복원 전 이용권 차감, 공개 완료와 해석 완료의 혼동을 발견하여 수정하고 회귀 테스트를 보강했다.

이번 작업은 로컬 적용이다. 기존 미커밋 작업과 함께 유지했으며 Git 커밋·푸시·배포는 수행하지 않았다. 파일 저장은 단일 Node 서버용으로, 여러 서버가 같은 디렉터리에 동시 쓰기 하는 배포 구조는 지원하지 않는다. 실제 배포에서는 공유 저장소와 로그인 기반 기록 접근을 별도로 설계해야 한다.

## 자연스러운 진행 및 대화 노트 수정

리딩 방식·배치 선택 UI를 제거했다. 새 상담은 adaptive 정책으로 사연에 맞춰 관점을 연결한다. 시작 안내에서 시간·이용권 수·정책 데이터를 제거하고, 내부 상태에 대한 확인·낭독을 금지했다. 노트에는 타임스탬프, 발언자, 상담 단계, 당시 질문·배치·카드 그룹을 남긴다. 음성 인식 결과가 늦게 도착해도 발화 시작 시점의 단계로 저장한다. 실제 사용자 발언, 시범 사연, 진행 기록을 구분하고 종료 화면과 리포트에서 제공한다. 자동 테스트 36개 통과.
