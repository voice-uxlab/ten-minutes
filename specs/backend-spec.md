## 2. 백엔드 기술 스택 및 선정 사유

| 항목 | 초안 | 선정 사유 / 상태 |
|---|---|---|
| 언어 | **Python** | Java 등 다른 언어나 백엔드 개발에 익숙하지 않은 팀원도 함께 구현할 수 있도록 학습 부담을 고려해 선정 — **제안** |
| API 프레임워크 | **FastAPI** | Python으로 로그인·결제·상담 관리 API를 구현하기 위한 프레임워크로 선정. 입력값 검증과 API 문서 자동 생성 기능을 활용해 구현·연동 작업을 줄이려는 목적 — **제안** |
| 데이터베이스 | **PostgreSQL** | 사용자·결제·이용권·상담 기록을 SQL로 관리하기 위한 관계형 DB로 선정. 결제와 이용권 갱신을 트랜잭션으로 처리하고, Supabase 같은 관리형 서비스와 직접 설치 방식 중 운영 환경에 맞게 선택하려는 목적 — **제안** |
| 음성 연동 | **OpenAI Realtime API** | 음성 통신 방식 및 서버 연결 구조는 PoC 이후 확정 — **검토 중** |
| 결제 | **간편결제/PG 제공사 미정** | 결제 방식 확정 후 서버 측 승인 검증과 거래 기록 처리 |
| 호스팅 | **Vercel Functions / AWS Lightsail 비교 검토** | 초기 고정비, 운영 부담, 실행 제약을 비교한 후 결정 — **미확정** |

※ Python/FastAPI 코드는 호스팅 환경이 바뀌어도 옮길 수 있도록 구성하고, 클라우드 전용 서비스에 대한 의존은 최소화한다.

## 3. 백엔드 담당 범위

- **인증·계정:** 소셜 로그인 연동, 사용자 식별, 닉네임 저장
- **상담 세션:** 이용권 잔액 확인, Realtime 연결을 위한 서버 측 인증, 시작·종료 기록
- **카드 데이터:** 78장 카드 정보 제공, 선택한 카드 기록
- **결제·이용권:** 결제 결과 검증, 이용권 구매·사용·잔액 기록 및 중복 차감 방지 — **미확정**
- **상담 리포트:** 상담 종료 후 요약 요청, 생성 결과 저장·조회
- **프롬프트 정책:** 페르소나·해석 지침의 관리 주체 및 방식 — **미확정**

> 현재 초안에서는 별도의 상시 실행 백엔드 서버나 자체 음성 스트리밍 중계를 필수로 두지 않는다.  
통화 중 서버의 지속 연결이 필요한지는 PoC에서 확인한다.

## 5. 최소 API 목록 (설계 초안)

> 아래 경로는 백엔드가 처리할 기능을 설명하기 위한 **예시**다. FastAPI 도입 여부와 실제 엔드포인트는 팀 검토 후 확정한다.

| 구분 | API 예시 | 목적 |
|---|---|---|
| 사용자 | `GET /users/me` | 로그인 사용자 및 닉네임 조회 |
| 이용권 | `GET /credits` | 남은 이용권 확인 |
| 결제 | `POST /payments/confirm` | 결제 승인 검증 및 이용권 지급 |
| 상담 시작 | `POST /sessions` | 이용권 확인 및 음성 세션 준비 |
| 상담 종료 | `POST /sessions/{id}/end` | 상담 종료 기록 및 이용권 정산 |
| 상담 리포트 | `GET /sessions/{id}/report` | 리포트 생성 상태와 결과 조회 |

소셜 로그인 콜백, 닉네임 변경, 결제사 웹훅, 리포트 생성 트리거 등은 연동 방식이 정해질 때 추가한다. API 개수와 경로는 확정 사항이 아니다.

## 7. 인프라 후보 및 선정 기준

| 기준 | Vercel Functions | AWS Lightsail |
|---|---|---|
| 요청을 받아 처리하는 API | 적합 | 적합 |
| FastAPI 배포 | 지원 (실행 제약 검증 필요) | 일반 서버로 배포 가능 |
| 결제 검증·DB 연동 | 가능 | 가능 |
| 인프라 운영 | 관리 부담 적음 | OS·배포·보안·백업 직접 관리 |
| 확장 | Functions 자동 확장 | 인스턴스 증설 또는 구조 변경 필요 |
| 상시 프로세스·직접 서버 제어 | 제약 검토 필요 | 상대적으로 자유로움 |
| **결정 상태** | **후보** | **후보** |

**선정 기준:** (1) MVP 기능 충족, (2) 월 총운영비, (3) 배포·관리 부담, (4) 음성 세션 및 리포트 처리 제약, (5) 향후 이전·확장의 편의성.

## 9. 환경 설정 및 준비 시점

| 단계 | 준비 범위 |
|---|---|
| **지금: 명세 단계** | 기술 후보·백엔드 담당 기능·데이터 엔터티·예상 비용 비교. **계정 및 서버 생성 불필요** |
| **PoC/로컬 개발** | Python 가상환경, FastAPI, `.env`, 개발용 DB, API 키가 외부에 노출되지 않도록 설정, 기본 로그 |
| **통합 테스트** | 선정한 호스팅 환경 배포, HTTPS, 환경변수/시크릿 설정, 결제 테스트·이용권 검증 |
| **MVP 배포 전** | 오류 모니터링, 백업 및 복구 방법, 비용 알림·사용량 상한, 접근 권한 점검 |

AWS를 선택할 경우에만 계정 생성·결제 수단·MFA·IAM·비용 알림을 준비한다.  
계정 및 비용 관리 담당자는 **미정**이다.

## 11. 향후 확장 시 고려사항

> 본 항목은 MVP 개발 범위에 포함하지 않으며, 서비스 운영 이후 확장을 위한 참고 기준이다.

| 항목 | 확장 기준 및 검토 사항 |
|---|---|
| 사용자 규모 | 전체 사용자 1,000명, 동시 음성 상담 100명 가정 |
| 백엔드 | API 응답시간, 동시 요청 처리 및 오류율 점검 |
| 데이터베이스 | 동시 연결 수, 쿼리 성능 및 데이터 정합성 검증 |
| 음성 세션 | 동시 세션 관리, Tool Calling 처리 지연 및 연결 안정성 확인 |
