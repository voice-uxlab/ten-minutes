# F02 - 고민 구체화

> 상태: 팀 검토용 초안. 구현 범위와 완료 조건을 검토하기 위한 문서입니다.

## 목적

사용자의 자유로운 고민을 카드로 살펴볼 상담 질문 한 문장으로 정리하고 확인받는다.

## 책임 범위

- 소유: 상담 시작 인사와 고민 질문, 추가 질문, 질문 초안 표시, 수정, 사용자 확인, 확정 질문 발행.
- 경계: 음성 연결과 종료는 F01, 확정 질문을 받은 후 카드 UI 활성화와 선택 안내는 F03, 카드 해석은 F04가 담당한다.
- 완료 시점은 확정 질문 발행까지다. 카드 화면이나 해석이 동작하는지는 F02의 완료 기준이 아니다.

## 기본 흐름

1. 상담 시작 시 인사하고 고민을 묻는다.
2. 필요한 경우 추가 질문을 한다.
3. 상담 질문을 한 문장으로 제안하고 화면에도 표시한다.
4. 수정 요청을 반영하고 사용자에게 다시 확인한다.
5. 사용자 확인 후 확정 질문을 발행한다.

## 대화 예시

고정 대본이 아닌 동작 예시다.

- 사용자: “요즘 회사에서 고민이 많아요.”
- 타로 리더: “어떤 부분이 가장 마음에 걸리세요?”
- 사용자: “다른 팀으로 옮길지 고민이에요.”
- 타로 리더: “‘팀 이동을 앞두고 어떤 점을 살펴보면 좋을까?’라는 질문으로 살펴볼까요?”
- 사용자: “네.”
- 결과: 해당 질문을 확정하여 발행한다. 카드 선택 안내는 여기서 하지 않는다.

## 동작 규칙

- 질문이 명확하면 추가 질문을 생략한다.
- 추가 질문은 한 번에 하나씩, 원칙적으로 2회 이내로 한다. 정보가 부족하면 넓은 질문을 제안한다.
- “그냥 뽑고 싶어요”에는 자세한 사정을 요구하지 않고 일반적인 자기 성찰 질문을 제안한다.
- 여러 고민은 이번 상담에서 다룰 하나를 고르도록 돕는다.
- 확인 전까지 질문은 초안이다. 수정 후에도 다시 확인받는다.
- 카드 확정 전 질문 변경 요청이 전달되면 질문을 수정하고 재확인한다.
- 질문 확인과 무관한 발화를 확인 응답으로 처리하지 않는다.
- 사용자에게 없는 사정을 추가하거나 전문적 판단을 타로 질문으로 확정하지 않는다.

## 입력과 결과

- 입력: 상담 시작 신호, 사용자 고민/수정/확인 발화, 카드 확정 전 질문 수정 요청.
- 결과: 화면에 표시할 질문 초안, 확인 질문, 확정 질문.
- 확정 질문에는 세션 식별자, 질문 식별자, 질문 버전, 질문 문장을 포함한다. 필드명과 내부 형식은 구현 시 정한다.
- 같은 확인 발화의 중복 처리로 같은 버전의 확정 결과를 여러 번 발행하지 않는다.
- 확정은 사용자 확인 후에만 발생한다.

## 실패 및 예외

- 알아듣지 못했거나 응답이 모호하면 다시 묻고 확정 결과를 발행하지 않는다.
- 질문 생성 실패 시 기존 초안을 유지하고 다시 시도할 수 있도록 안내한다.
- 세션 종료 신호를 받으면 미확정 질문 처리를 중지한다. 연결 해제는 직접 수행하지 않는다.

## 완료 조건

아래 항목을 모두 통과하면 F02 구현 완료로 판정한다.

- [ ] AC01: 넓은 고민을 추가 질문으로 상담 질문 한 문장으로 정리한다.
- [ ] AC02: 명확한 고민은 불필요한 추가 질문 없이 확인 단계로 진행한다.
- [ ] AC03: 화면 질문과 사용자에게 확인한 문장이 일치한다.
- [ ] AC04: 수정 후 재확인하며 확인 전에는 확정 결과가 없다.
- [ ] AC05: 확인 후 해당 질문 버전의 확정 결과를 한 번 발행한다.
- [ ] AC06: 자세한 고민이 없는 경우와 여러 고민이 있는 경우 모두 질문 하나로 정리한다.
- [ ] AC07: 모호한 응답이나 생성 실패 시 임의 확정하지 않는다.
- [ ] AC08: 카드 확정 전 수정 요청에 새 버전 질문을 제안하고 확인 후 발행한다.

## 독립 검증 방법

음성 전송 대신 미리 작성한 발화 텍스트를 입력하고 질문 UI와 확정 결과를 확인한다. 카드 UI는 구현하지 않고 확정 결과를 받는 테스트 수신부로 대체한다. 음성 품질, 카드 선택 가능 여부, 해석 품질은 판정에서 제외한다.
