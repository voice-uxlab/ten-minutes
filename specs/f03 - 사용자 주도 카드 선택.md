# F03 - 사용자 주도 카드 선택

> 상태: 팀 검토용 초안. 이 대화에서 작성한 MVP 제안이며, 이 파일의 커밋만으로 팀의 구현 준비 완료나 PRD.md의 미정 항목 확정을 의미하지 않습니다.
>
> 마일스톤: [최소 사용자 흐름](feature-list.md). 흐름: 이용 안내 확인 → 음성 대화 시작 → 고민 구체화 → 터치로 카드 선택 → 카드 해석 → 후속 대화 → 종료.

## 목적

AI에게 추첨을 맡기는 대신, 사용자가 덱에서 자신의 카드를 직접 골랐다고 느끼도록 한다. 첫 버전은 터치 선택을 기본으로 한다.

## 시작 조건 및 의존성

F01 세션이 연결되어 있고 F02에서 상담 질문이 확정되었다. 카드 덱과 카드별 ID, 이름, 이미지 자산이 필요하다.

## 기본 흐름

1. 메이저 아르카나 22장의 뒷면 카드를 펼쳐 보여준다.
2. 타로 리더는 선택을 안내한 뒤 기다린다.
3. 사용자가 카드를 탐색하고 한 장을 터치한다.
4. 선택 카드를 강조하고 나머지 카드 선택을 잠근다.
5. 선택 카드가 뒤집히며 이름과 이미지를 공개한다.
6. 앱이 카드 결과를 AI에 전달하고 F04 해석을 시작한다.

## 동작 규칙

| 항목 | 요구사항 |
|---|---|
| 덱 | 초안 제안은 메이저 아르카나 22장, 정방향만 사용한다. |
| 카드 배정 | 덱 표시 시 순서를 무작위로 정하고 각 위치의 카드 정체를 고정한다. |
| 탐색 | 모바일에서도 22장에 접근할 수 있도록 가로 스크롤을 제공한다. |
| 선택 확정 | 첫 번째 유효한 터치로 한 장을 확정한다. |
| 결과 공개 | 선택 위치에 미리 배정된 카드를 공개한다. |
| 중복 방지 | 연속 터치나 전달 재시도로 추가 카드를 뽑지 않는다. |
| 대화 연결 | 확정된 카드 ID와 이름을 AI에 전달한다. 화면 카드와 AI 해석 대상은 동일해야 한다. |
| 기다림 | 선택 전에는 임의로 고르거나 해석하지 않고 재촉하지 않는다. |
| 상태 유지 | 화면 크기 변경이나 재렌더링으로 덱 순서와 선택 결과를 변경하지 않는다. |

## 입력과 결과

- 입력: 확정된 상담 질문, 사용자 카드 터치.
- 결과: 선택 카드 ID/이름/이미지, 선택 확정 상태, AI에 전달할 카드 결과.
- 종료 조건: 선택 결과를 F04로 전달하거나 세션을 종료한다.

## 실패 및 예외

- “네가 골라줘”: 직접 고르도록 안내한다. 음성으로 대리 추첨하지 않는다.
- 결과 전달 실패: 선택 카드를 유지하고 재시도 버튼을 제공한다. 재시도는 같은 결과를 전달한다.
- 카드 확정 전 질문 변경: F02으로 돌아가 질문을 수정한다. 카드 재배치나 추첨을 발생시키지 않는다.
- 종료 후 지연 도착한 결과: 새 상담에 반영하지 않는다.

## 완료 조건

- [ ] 카드 뒷면 22장을 탐색하고 한 장을 터치할 수 있다.
- [ ] 탐색과 화면 크기 변경 중 위치별 카드 정체가 바뀌지 않는다.
- [ ] 연속 터치해도 카드 한 장만 확정된다.
- [ ] 공개된 카드와 AI에 전달된 카드가 일치한다.
- [ ] 선택 후 별도 음성 명령 없이 해석으로 이어진다.
- [ ] 결과 전달 재시도 시 같은 카드가 유지된다.
- [ ] AI가 사용자를 대신해 카드를 선택하지 않는다.

## 제외 범위

음성 위치 선택, AI 대리 선택, 여러 장 배열, 역방향, 재추첨, 생성형 카드 이미지, 선택 방식 비교 실험.

## 관련 기능 및 결정

- 선행: F01, F02. 후행: F04.
- PRD.md 관련 결정: T01–T03, D05, V03.
- 미결정: 22장/정방향 규칙은 이 초안의 제안이며 팀 검토가 필요하다. 이미지 자산 출처와 사용 권한, 카드 목록 및 UI 배치는 구현 전 확정한다.

## 공통 요구사항

- 한 세션에서 질문 하나와 카드 한 장을 다룬다.
- 상담 질문, 선택 카드, 진행 단계는 앱이 관리한다. AI 발화만으로 카드 선택이나 단계 완료를 확정하지 않는다.
- 앱 DB에 음성, 대화 원문, 상담 결과를 영구 저장하지 않는다. 종료 시 세션의 대화 및 카드 상태를 초기화한다.
- 시작 전에 AI 음성, 오락 및 자기 성찰 목적, 외부 API 전송과 데이터 처리 방식을 안내한다.
- 지원 목표는 iPhone Safari와 데스크톱 Chrome이며 실제 기기에서 전체 흐름을 검증한다.
- 로그인, 앨범, 이미지 생성, 자막, 관리자 분석, 연구 데이터 수집과 파라미터 실험은 이번 범위에서 제외한다.
